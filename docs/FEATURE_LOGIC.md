# 功能逻辑与交接说明

> 本文说明导入、审核、发布、编辑、删除、阅读之间的关系，避免“审核过了却看不见”“上传后不知道去哪”“作者名一改全变”这类问题。

## 1. 导入解析逻辑

优先级：**只按源文件目录/章节标题生成最终章节；技术分片仅用于解析与批量写入，对用户不可见**。

### 1.1 标题规则

支持以下独立成行的章节标题：

- 中文：`第一章`、`第1章`、`第 100 回`、`第一百二十三节`
- 括号：`【第 N 章】`、`[第 N 章]`
- 英文：`Chapter 1`
- 特殊章节：`序章 / 楔子 / 尾声 / 番外`
- 分隔线：连续 3 个及以上 `-`、`=`、`_`、`*`（如 `---`、`-----`）；有目录时只做内容分隔，无目录时可作为章节边界
- 卷标题：`第一卷`、`第 1 卷` 作为分组提示

### 1.2 目录与兜底拆分

- 有章节标题时，章节结构完全来自源文件目录；分隔线不生成“第 N 章”虚拟标题。
- 没有章节标题时，可设置每章字数按段落累计兜底拆章，分隔线也可作为章节边界。
- 大文件解析后按章拆包写入 R2、按 12 章一片提交 D1，分片只发生在传输/写入层。
- 有目录时超长单章保留为单个原始章节，仅提示“建议拆分”，不自动切成“续章”。
- 同标题且正文相同的章节自动过滤，正文不同则全部保留；不弹“大量重复标题”类提醒。

### 1.3 新建作品 vs 已有作品

- **新建作品**：上传文件时创建一个新书，文件名为书名（可填标题覆盖）。
- **已有作品**：把文件解析出的章节**追加到该书**，不会新建书；确认导入后新章节排在该书现有章节之后。

## 2. 章节生命周期

```text
草稿(draft) → 审核中(pending_review) → 已发布(published)
                   ↘ 退回(rejected) → 修改后重新提交
```

- 导入确认后可选择“导入后直接提交审核”（默认开），否则先存为草稿。
- 章节编辑：草稿、被退回、**已发布**章节都可直接编辑，编辑保存生成新的不可变版本；已发布章节保存后公开内容立即更新（版本可追溯）。
- 章节删除：任何状态的章节都可直接删除（审核中的章节会同步清理审核任务），删除后公开接口 404、目录不再显示，作品字数与最新章节自动重算。
- 公开阅读接口只放行 `published` 章节，草稿/审核中/被退回一律 404。

### 下架（作品级）

- “下架作品”作用于整本书：书状态变为 `suspended`，从首页、分类、榜单、搜索结果隐藏；详情页和已发布章节仍可通过链接访问。
- “重新上架”恢复 `published`，重新出现在首页/榜单。
- 章节没有单独的下架按钮，编辑页直接编辑或删除即可。

## 3. 审核与发布

- 审核工作台按作品归集待审章节，支持整本书“全部通过”和勾选批量通过。
- 批量通过使用批量 SQL，不再逐章循环，避免大书触发 Worker 1102。
- **审核通过 = 发布**：章节变为 `published`，同时书状态自动变为 `published`，公开首页/详情/阅读器立即可见。
- 审核退回必须填写原因，作者会收到通知。

## 4. 删除规则

- 作者在作品管理页可删除整本书：审核记录、标签、导入任务、章节版本、章节、卷、书全部清库，按子表顺序删除避免外键报错；删除成功后页面立即刷新。
- 审核工作台每本书也有“删除”按钮，权限为管理员/审核员；删除后列表立即刷新。
- R2 中的历史正文对象暂不物理删除，数据库不留数据。

## 5. 作者名

- 每个账号有一个全局默认笔名（`authors.pen_name`），首次成为作者时自动生成。
- **每本书可以单独设置作者名**（`books.author_name`），展示时优先用本书作者名，未设置才回退全局笔名。
- 修改一本书的作者名不会影响其他书，也不会改全局笔名。

## 6. 阅读器

- 默认“覆盖”翻页模式：当前屏幕只显示一页内容，点击左右区域、键盘方向键、移动端左右滑动进入上一页/下一页。
- 阅读器目录右上角有“倒序/正序”切换，默认倒序（最新章节在前）。
- 夜间模式：网站深色模式下首次进入阅读器默认使用墨水灰主题；阅读器内可手动切换明亮/柔和/羊皮纸/墨灰/OLED。
- 超大章节（超过 8000 段或 100 万字）阅读时返回明确提示，不渲染，避免卡死/1102。

## 7. 资源限制（防 1102）

- 单本上传上限：TXT/EPUB/MOBI/PDF 均为 50MB；超过 50MB 走 R2 分片上传。
- 单本最多 5000 章；单章超过 4000 段或 40 万字保留为单章并提示“建议拆分”。
- 解析异步走 Cloudflare Queues，上传请求立即返回，前端轮询任务状态。
- 批量审核、批量提审都使用批量 SQL，避免逐条循环耗尽预算。
